# SDY-г өөрөө дарааллаар нь шалгах заавар

**2026-09-16-нд production-д гарсан `72112a97` хувилбарт зориулсан.**

> **13:54 шинэчлэлт:** eID QR хүсэлт үүсгэх үед provider 404, SDY 502 өгч байсан.
> 2026-09-22-нд сэргэсэн (eID RP API `https://rp.eidmongolia.mn` руу шилжсэн);
> T02 нэвтрэлтийн шалгалтыг дахин хийж болно.
Энэ бол та өөрөө гүйцэтгэж үр дүнгээ тэмдэглэх заавар; энд бичсэн шалгалтуудыг
таны төхөөрөмж дээр хийсэн гэж тооцоогүй.

**Үндсэн дараалал:** Нүүр → eID → элсэлт → хувийн бүртгэл → арга хэмжээ →
QR/оноо → мэдэгдэл → эрх → хураамж → тайлан → шилжилт → хуучин түүх →
гишүүнчлэлийн төлөв → утсанд суулгах/offline.

[Excel/Sheets-д нээх checklist](SDY_MANUAL_TEST_CHECKLIST_2026-09-16.csv) дахь
`Үр дүн` баганад **PASS / FAIL / БЭЛТГЭЛ ДУТУУ / АЛГАСАВ** гэж бичнэ.
Анх бүгд **ШАЛГААГҮЙ**. Өөрийн харсан үр дүнгээр бөглөнө.

## 0. Эхлэхээс өмнө

### Хэнээр шалгах вэ?

| Тэмдэглэгээ | Хэрэгтэй эрх | Юунд ашиглах |
| --- | --- | --- |
| **T — гишүүн** | Энгийн `user`; admin/manager болон нэмэлт ажилтны эрхгүй | Элсэх, profile, ирц, төлөлт, шилжих, түдгэлзэх |
| **M — manager** | A салбарын manager; санхүүгийн нэмэлт эрхгүй | Элсэлт шийдэх, арга хэмжээ/ирц, эрхийн хязгаар |
| **A-admin** | A салбарын бодит admin | Үндсэн харьяалал, санхүү, эрх |
| **B-admin** | B салбарын бодит admin | Шилжин ирэх хүсэлт, шинэ салбарын бүртгэл |
| **U — хоёр дахь гишүүн** | Энгийн user, боломжтой бол A салбарт | Багтаамж, бусдын мэдээлэл, тусдаа туршилтууд |

A/B-admin нь хоёр салбарт ажиллах эрхтэй **нэг хүн байж болно**. T нь тэднээс
тусдаа хүн байна. T-г admin болгож шалгавал энгийн гишүүний эрхийн шалгалт буруу болно.
U байхгүй бол U шаардсан дэд шалгалтыг `БЭЛТГЭЛ ДУТУУ` гэж тэмдэглэнэ.

- **A = одоогийн салбар, B = очих салбар.** Жишээ нь Дархан → Орхон;
  бодит хүнээр шалгахдаа тухайн хүний зөв харьяаллыг ашиглана.
- T-г утас, M/A-admin-ийг компьютерийн **өөр browser profile** эсвэл өөр
  browser дээр нээнэ. Нэг browser-ийн олон private/incognito цонх session-оо
  хуваалцаж болох тул тэдгээрийг тусдаа хэрэглэгч гэж бүү тооц.
- Үйлдэл бүрийн өмнө толгой хэсэгт **зөв хүн, зөв салбар** байгааг харна.
- Төхөөрөмжийн цаг/бүсийг Улаанбаатарт тохируулна. Туршилтын event-ийн
  нэрийг `ШАЛГАЛТ-YYYYMMDD-HHMM` гэж ялгана.
- Анхны оноо, тухайн сарын хураамж/төлөлт/үлдэгдэл, үндсэн харьяаллыг тэмдэглэнэ.
  Өмнөх түүхтэй бол доорх өөрчлөлтийг анхны дүн дээр нэмэх/хасах байдлаар тулгана.

**Production дээр хадгалсан үйлдэл бодит түүх болно.** Хураамж ногдуулах нь
сонгосон нэг хүнийг бус, салбарын тухайн сард ногдуулалтгүй бүх идэвхтэй үндсэн
гишүүнийг хамарна. Жишээ тариф, зохиомол төлөлт, олон удаагийн шилжилт/төлөвийн
туршилтыг тусгаарласан тестийн орчинд хийнэ. Доорх 10,000₮/4,000₮ нь зөвхөн
тооцоог тайлбарлах жишээ; production-д байгууллагын батлагдсан дүн, бодит данс,
үнэн гүйлгээг хэрэглэнэ. Тусдаа тестийн сайтын хаяг энэ баримтад заагаагүй.
Тохиргоо эсвэл орчин бэлэн биш бол тухайн хэсгийг `БЭЛТГЭЛ ДУТУУ` гэж үлдээнэ.

### Manager бэлэн биш бол

A-admin [гишүүний нүүр](https://e-sdy.mn/member)-ээс A салбараа нээгээд
[Эрхийн тохиргоо](https://e-sdy.mn/settings/access) → **Хэрэглэгчид** табд орно.
Өмнө нь A салбарт зөвшөөрөгдсөн M хүнийг нэр/имэйлээр тулгаж, **manager** role-ийг
сонгоно. Role оноолт шууд хадгалагдана; M дахин нэвтэрч шалгана.
**Role ба эрх** таб дахь бүх manager-т үйлчлэх эрхийг энэ туршилтаар өөрчлөхгүй.
Хүн жагсаалтад байхгүй бол эхлээд 3–4-р алхмаар элсүүлнэ.

## 1. Нүүр хуудас — T01

1. Нэвтрээгүй browser-оор [e-sdy.mn](https://e-sdy.mn) нээнэ.
2. Гар утасны босоо/хэвтээ байрлал болон компьютер дээр харна.
3. **Элсэх заавар**, **Түгээмэл асуулт** холбоос, асуултын дэлгэдэг мөрүүдийг дарна.
4. **e-ID-аар нэвтрэх** дарна.

**Хүлээгдэх:** лого, монгол текст, товчнууд харагдана; хэвтээ тийш илүү гүйлгэх
шаардлагагүй; холбоос зөв хэсэгт хүргэнэ; нэвтрэх дэлгэц нээгдэнэ.
Нүүрийн танилцуулгын зураг/тоо нь таны бодит хувийн бүртгэлийн тайлан биш.

## 2. eID нэвтрэлт — T02

1. T өөрийн eID Mongolia-гаар нэвтрэх үйлдлийг эхлүүлнэ.
2. Компьютер дээр эхэлсэн бол eID-ийн зааврын дагуу QR/хүсэлтээ батална.
   Утаснаас эхэлсэн бол eID апп руу шилжиж зөвшөөрөөд эхэлсэн browser/PWA руу буцна.
3. [Гишүүний нүүр](https://e-sdy.mn/member)-д зөв хүний нэр гарсныг шалгана.
4. Хуудас шинэчлээд, дараа нь хэрэглэгчийн цэсээр гараад дахин eID-ээр нэвтэрнэ.

**Хүлээгдэх:** өөрийн бүртгэлд буцаж орно; өмнөх хүсэлт/харьяалал/түүх хадгалагдана.
Энэ мөчид буруу хүн харагдвал дараагийн бичилт хийхгүй, T02 дээр алдааг тэмдэглэнэ.
Нэвтрэх нууц, OTP, QR token-ийг checklist-д хуулж бичихгүй.

## 3. Элсэх хүсэлт — T03

**T нь үндсэн харьяалалгүй үед.** Аль хэдийн гишүүн бол шинэ T/U-аар энэ хэсгийг шалгана.

1. **Нүүр → Салбараа сонгоно уу** хэсгийг нээнэ.
2. Дархан-Уул аймаг болон Дархан, Орхон, Шарын гол, Хонгор дөрвөн сум
   харагдаж байгаа эсэхийг шалгана. A салбараа сонгоно.
3. **Нэмэлт тайлбар** бичээд **Элсэх хүсэлт илгээх** дарна.
4. Нүүрээ шинэчилнэ. Хүлээгдэж байхад ижил салбарт дахин илгээж үзнэ.
5. Батлагдахаас өмнө A салбарын арга хэмжээ, гишүүдийн удирдлагыг нээхийг оролдоно.

**Хүлээгдэх:** **Шийдвэр хүлээж байна**; manager-ийн дараалалд нэг pending хүсэлт;
хүсэлт өгсөн төдийд салбарын хувийн мэдээлэл/удирдлагын эрх нээгдэхгүй.
Хэрэв шууд батлагдвал салбарын элсэлтийн бодлого өөрчлөгдсөн эсэхийг админтай тулгана.

## 4. Элсэлтийг шийдэх — T04–T05

1. **M, A салбар**: [Элсэх хүсэлтүүд](https://e-sdy.mn/member/requests) нээнэ.
2. T-ийн нэр, имэйл, тайлбарыг тулгана.
3. Татгалзах урсгалыг шалгаж байгаа бол **Татгалзах** дарна; T нүүрээ шинэчлээд
   татгалзсан төлөв, салбарын эрхгүй хэвээр байгааг харна. Дараа нь шинэ хүсэлт илгээнэ. **T04**
4. M хүсэлтийг **Батлах** дарна. **T05**
5. T **Нүүр → Шинэчлэх → Салбар руу орох** дарна.
6. **Бүртгэл / Миний гишүүнчлэл** нээж A нь **Үндсэн харьяалал · Идэвхтэй**,
   эхэлсэн огноо, элсэлтийн түүхтэй байгааг шалгана.

**Хүлээгдэх:** энгийн гишүүний эрх үүснэ; admin/manager эрх автоматаар нэмэгдэхгүй.
M зөвхөн идэвхтэй сонгосон салбарынхаа хүсэлтийг шийднэ.

## 5. Хуучин бүртгэлийн үндсэн харьяалал — T06

Энэ хэсгийг зөвхөн **Гишүүнчлэл баталгаажаагүй** гэсэн хуучин бүртгэлд хийнэ.

1. A-admin зөв салбараа сонгоод [Гишүүдийн бүртгэл](https://e-sdy.mn/member/members)-д
   нэр/имэйлээр хайна.
2. **Үндсэн харьяалал батлах** → **Идэвхтэй** → бодит шалтгаан → **Хадгалах**.
3. Тухайн хүн дахин нэвтэрч **Үндсэн харьяалал** ганц байгааг шалгана.

**Хүлээгдэх:** ажилтны бусад салбарт ажиллах эрхээс үндсэн харьяаллыг ялгаж харуулна.
Өөр салбарт үндсэн харьяалалтай хүнийг эндээс давхар батлахгүй; шилжих хүсэлт шаарддаг.
Олон салбарт ажиллах эрхтэй админы харьяаллыг туршилтын тулд дур мэдэн сонгохгүй.

## 6. Хувийн бүртгэл — T07

1. T [Миний гишүүнчлэл](https://e-sdy.mn/member/record) → **Холбоо барих мэдээлэл**.
2. Өөрийн утас, оршин суугаа аймаг/сумыг бичээд **Хадгалах**.
3. Refresh, гарах/дахин нэвтрэхэд мэдээлэл хэвээр байгааг шалгана.
4. M [Гишүүдийн бүртгэл](https://e-sdy.mn/member/members)-ээс T-г хайна.

**Хүлээгдэх:** T өөрийн нэмэлт холбоо барих мэдээллээ засна. M-ийн жагсаалтад
T-ийн энэ хувийн утас/оршин суугаа мэдээлэл харагдахгүй. M өөрийн **Бүртгэл**
хуудсыг нээвэл өөрийнх нь profile гарна. Утас хадгалах нь OTP-оор баталгаажуулсан гэсэн үг биш.

## 7. Арга хэмжээ үүсгэх — T08

1. M/A-admin A салбарт [Арга хэмжээ](https://e-sdy.mn/module/events) → **Арга хэмжээ нэмэх**.
2. Нэр: `ШАЛГАЛТ-YYYYMMDD-HHMM`, эхлэх: шалгаж буй сарын огноо/цаг,
   дуусах: эхлэхээс хойш, байршил/тайлбар: туршилтын зорилгыг тодорхой бичнэ.
3. **Хүний дээд тоо** 2, **Батлагдсан ирцийн оноо** 10 гэж тусгаарласан тестэд тохируулна.
   Production-д зөвшөөрөгдсөн бодит оноог хэрэглэнэ; оноо олгохгүй танилцах бол 0.
4. **Хадгалах** → event-ээ нээж нэр, цаг, байршил, багтаамж, оноог тулгана.
5. T ижил салбарын жагсаалтаас event-ээ нээнэ.

**Хүлээгдэх:** M үүсгэж/засна; T-д **Арга хэмжээ нэмэх**, **Засах**, бусдын ирц
өөрчлөх товч байхгүй. Event-ийн нэрийг цааш бүх алхамд адил ашиглана.

## 8. Бүртгүүлэх ба цуцлах — T09–T10

1. T event дотор **Бүртгүүлэх** дарна; өөрийн төлөв **Бүртгүүлсэн** болно.
2. **Бүртгэлээ цуцлах**, дараа нь дахин **Бүртгүүлэх** дарна. **T09**
3. M оролцогчдын жагсаалтыг шинэчилж T нэг мөр байгааг шалгана.
4. Багтаамжийг тусад нь шалгах бол хүнгүй шинэ event-ийг 1 хүний дээд тоотой
   үүсгэнэ. T бүртгүүлсний дараа U бүртгүүлэхийг оролдоно. **T10**

**Хүлээгдэх:** бүртгүүлсэн төдийд ирц/оноо нэмэгдэхгүй; дүүрсэн event-д U-г нэмж
бүртгэхгүй. Давхар дарснаар T хоёр оролцогч болохгүй.

## 9. QR ирц ба давтан батлах — T11

1. M үндсэн event дотор **Ирц бүртгүүлэх QR гаргах** дарна.
2. T утасныхаа камераар M-ийн дэлгэц дээрх QR-ийг уншуулна.
3. Нээгдсэн дэлгэцийн event, оноог тулгаад **Би ирсэн — батлах** дарна.
4. **Таны ирц баталгаажлаа** гэдгийг хараад [Ирц](https://e-sdy.mn/member/participation) нээнэ.
5. Ижил хүчинтэй QR-ийг дахин уншуулж батална; refresh хийнэ.

**Хүлээгдэх:** нэг **Ирсэн** бүртгэл. 10 оноотой event бол анхны оноо дээр
**+10**, давтан баталснаар **+20** болохгүй. 0 оноотой бол ирц бүртгэгдэж,
онооны нийлбэр нэмэгдэхгүй. M-ийн ирцийн тоо мөн нэгээр нэмэгдэнэ.

## 10. QR-ийн хугацаа, нэвтрэлт — T12

1. T/U-д зориулсан тусдаа event дээр QR гаргаж, нээгээд батлалгүй 5 минутаас илүү хүлээнэ.
2. Хуучин кодоор батлахыг оролдоно: амжилттай шинэ ирц үүсэх ёсгүй.
3. Шинэ QR гаргаад түүгээр батална. Шинэ QR гаргасан мөчөөс өмнөх нь хүчингүй.
4. Нэвтрээгүй browser-оор шинэхэн QR нээж eID-ээр орж үзнэ.

**Хүлээгдэх:** хугацаа хүчинтэй, ижил browser руу буцсан бол ирцийн урсгал үргэлжилнэ.
eID өөр browser нээсэн эсвэл кодын 5 минут дууссан бол шинэ QR уншуулна.
Нэвтрэх eID QR ба арга хэмжээний ирцийн QR нь хоёр өөр зориулалттай.

## 11. Ирцийн залруулга — T13

1. M үндсэн event-ийн T мөрөн дээр **Ирээгүй** эсвэл **Буцаах** дарна.
2. **Ирцийн залруулга** цонхонд шалтгаан хоосон үед **Хадгалах** идэвхгүйг шалгана.
3. Тусгаарласан тестэд шалтгаан бичээд хадгална.
4. T **Миний оролцоо, төлөлтийн түүх → Онооны өөрчлөлтүүд**-ийг харна.
5. M T-ийн ирцийг дахин **Ирсэн** болгож, T нийлбэрээ шалгана.

**Хүлээгдэх:** 10 онооны жишээнд **+10 → −10 → +10**, эцсийн цэвэр нэмэгдэл 10.
Хуучин түүх алга болохгүй. Ирц батлагдсан event-ийн онооны хэмжээг өөрчлөх оролдлого
хадгалагдахгүй. Production-ийн үнэн ирцийг зөвхөн бодит залруулгын шалтгаанаар өөрчилнө.

## 12. Мэдэгдэл — T14–T15

1. T [Мэдэгдэл](https://e-sdy.mn/member/notifications) нээж элсэлт, event,
   бүртгэл/ирцийн мэдэгдлийг харна.
2. Нэгийг **Уншсанд тооцох**, дараа нь **Бүгдийг уншсанд тооцох** дарна.
3. Refresh хийж уншаагүй тэмдэг арилсныг шалгана; мэдэгдлийн түүх үлдэнэ.
4. Одоо эрхтэй салбарын event мэдэгдлийн **Дэлгэрэнгүй үзэх**-ийг дарна:
   зөв салбар, зөв event нээгдэх ёстой. **T14**
5. **Бүртгэл → Апп дотор шинэ мэдэгдэл хүлээн авах**-ыг унтрааж **Хадгалах**.
6. M туршилтын event-ийн байршлыг өөрчилнө. T мэдэгдлээ дахин ачаална:
   энэ өөрчлөлтийн шинэ мэдэгдэл үүсэхгүй, хуучин мэдэгдэл үлдэнэ.
7. T тохиргоогоо буцааж асаан хадгална. M байршлыг дахин өөрчилнө:
   дараагийн өөрчлөлтийн мэдэгдэл ирнэ. **T15**

Нэр/тайлбарыг дангаар солих бус **эхлэх цаг, байршил, төлөв** өөрчлөхөд
мэдэгдэл үүсдэг. Push, SMS, имэйл хүлээхгүй; энэ нь апп доторх inbox.
Уншсанд тооцох болон дэлгэрэнгүй нээх нь тусдаа үйлдэл.

## 13. Эрхийн хязгаар — T16

A салбарт нэвтэрсэн T, M, A-admin тус бүрээр шууд холбоосыг нээнэ.

| Дэлгэц/үйлдэл | T энгийн гишүүн | M manager, санхүүгийн эрхгүй | Admin |
| --- | --- | --- | --- |
| Өөрийн бүртгэл/түүх/мэдэгдэл | Өөрийнх | Өөрийнх | Өөрийнх |
| Элсэх хүсэлт шийдэх | Эрхгүй | Болно | Болно |
| Гишүүдийн бүртгэл хайх | Эрхгүй | Болно | Болно |

| Шилжих хүсэлтүүд | Эрхгүй | Эрхгүй | Зөвхөн очих салбарын хүсэлт |

**Хүлээгдэх:** зөвхөн цэс нуух бус, URL-ийг шууд нээсэн ч хамгаалагдсан өгөгдөл/үйлдэл
гарч ирэхгүй. M-д тусгай санхүүгийн role өмнө олгосон бол санхүү харагдах нь алдаа биш;
эрхгүй manager-аар шалгана. Event-д бусдын нэр харагдаж болно, харин энгийн T-д
оролцогчдын имэйл болон зохион байгуулагчийн дотоод тэмдэглэл харагдахгүй.

## 14. Сарын хураамж — T17–T18

**Бэлтгэл:** санхүүгийн туршилтын зөв орчин эсвэл бодитоор хэрэгжүүлэх батлагдсан тариф/сар.
Энэ бэлтгэлгүй бол одоогийн хоосон/тохируулаагүй дэлгэцийг шалгаад бичилттэй хэсгийг үлдээнэ.

1. A-admin [Хураамжийн санхүү](https://e-sdy.mn/member/finance) → **Хураамжийн тохиргоо**.
2. **Хураамж идэвхтэй**, сарын батлагдсан дүн, төлөх өдөр **1–28**, банк,
   данс, эзэмшигч, зааврыг тулгаад **Хадгалах**. **T17**
3. **Сар** сонгож **Сонгосон сарын хураамж ногдуулах** дарна.
4. T **Миний хураамж**-д сар, дүн, хугацаа, данс, үлдэгдлээ тулгана.
5. A-admin ижил сарыг дахин ногдуулна. **T18**

**Хүлээгдэх:** T идэвхтэй үндсэн гишүүн бол нэг charge үүснэ. Зөвхөн ажиллах эрхтэй,
үндсэн харьяалалгүй хүнд шинэ charge үүсэхгүй. Давтан дарахад T-ийн мөр/дүн давхардахгүй.
Дунд нь шинэ гишүүн нэмэгдсэн бол нийт шинээр ногдуулсан тоо 0-ээс их байж болно;
**T-ийн тухайн сарын мөрийг** тулгана. Дүн/сар тохиргоог дараа нь солих нь өмнөх charge-ийг өөрчлөхгүй.

## 15. Хэсэгчилсэн төлөлт — T19

Тэмдэглэгээ: **F = ногдуулсан дүн**, **P = F-ээс бага бодит төлөлт**.
Жишээ нь тусгаарласан тестэд F=10,000₮, P=4,000₮.

1. T **Миний хураамж → Шилжүүлгээ мэдээлэх** дарна.
2. P дүн, бодит банкны гүйлгээний дугаар оруулаад **Шилжүүлгээ мэдээлэх**.
3. **Баталгаажуулалт хүлээж байна** төлөвт paid нэмэгдээгүйг шалгана.
4. A-admin **Хураамжийн санхүү → Шилжүүлгийн түүх**-ээс зөв хүн/сар/гүйлгээг тулгана.
5. **Төлөлтийг батлах** → **Шалгасан тайлбар / шалтгаан** → **Хадгалах**.
6. T хуудсаа шинэчлээд **Баталгаажсан**, paid=P, balance=F−P байгааг шалгана.
7. Үлдэгдлээс их дүнг мэдээлэхийг оролдоход хадгалагдахгүйг шалгана.

| Жишээ төлөв | Ногдуулсан | Төлсөн | Үлдэгдэл |
| --- | ---: | ---: | ---: |
| Charge үүссэн | 10,000 | 0 | 10,000 |
| 4,000 мэдээлсэн, батлаагүй | 10,000 | 0 | 10,000 |
| 4,000 баталсан | 10,000 | 4,000 | 6,000 |

Шилжүүлгийн мэдээлэл нь өөрөө банкнаас мөнгө татахгүй. Нэг гүйлгээг шинэ мэдээлэл
мэт олон удаа бүү илгээ; refresh нь шинэ төлөлт үүсгэх ёсгүй.
Дараах шилжилтийн туршилтад энэ хэсэгчилсэн төлөлт/үлдэгдлийг суурь болгож тэмдэглэнэ.

## 16. Санхүүгийн нэмэлт залруулгууд — T20–T22

Үндсэн T-ийн дээрх түүхийг хадгалж, тусгаарласан орчны **тусдаа гишүүн/charge** дээр
доорх хувилбаруудыг шалгана. Production-д зөвхөн бодит шийдвэрээр хэрэгжүүлнэ.

| ID | Үйлдэл | Хүлээгдэх |
| --- | --- | --- |
| T20 | Pending төлөлт → **Татгалзах**, шалтгаан оруулах | Татгалзсан; paid нэмэгдэхгүй; шалтгаан/түүх хадгалагдана |
| T21 | Баталгаажсан P төлөлт → **Баталгаажуулалтыг буцаах**, шалтгаан | Paid P-ээр буурч, үлдэгдэл P-ээр өснө; буцаасан түүх үлдэнэ |
| T22 | Үлдэгдэлтэй charge → **Үлдэгдлээс чөлөөлөх**, шалтгаан | Үлдэгдэл 0, **Чөлөөлсөн**; paid болон банкны орлого нэмэгдэхгүй |

Бүгдэд шалтгаангүй хадгалах боломжгүй. Буцаасан/татгалзсан төлөлтийг ижил мөрөөс
дахин батлахгүй. Чөлөөлөлтийг UI-аас буцаах товч одоогоор байхгүй.
**Баталгаажуулалтыг буцаах** нь банкны мөнгийг буцаан шилжүүлэхгүй.

## 17. Салбарын нэгтгэл — T23

1. A-admin [Салбарын нэгтгэл](https://e-sdy.mn/member/overview) нээнэ.
2. Үндсэн гишүүд/хүсэлтүүдийг [Гишүүдийн бүртгэл](https://e-sdy.mn/member/members)-тэй тулгана.
3. Үндсэн event эхэлсэн сар болон ногдуулсан сараа сонгож оролцоо/санхүүг харна.
4. [Салбарын оролцооны тайлан](https://e-sdy.mn/member/activity)-тай event,
   бүртгэл, ирц, онооны өөрчлөлтийг тулгана.
5. M ижил нэгтгэл нээж санхүү болон шилжилтийн тоо харагдахгүйг шалгана.

**Хүлээгдэх:** өмнөх дүн дээр туршилтын өөрчлөлт нэмэгдсэн байна. Гишүүнчлэлийн тоо
одоогийн төлөв; оролцоо нь **сонгосон сард эхэлсэн event**-ээр, санхүү нь
**ногдуулсан сар**-аар тооцогдоно. Энэ дэлгэц сумдын нийлбэр аймгийн тайлан биш.

## 18. Шилжих хүсэлт цуцлах/татгалзах — T24–T25

**T нь A-д идэвхтэй үндсэн гишүүн байна.** Бодит шилжилтээр шалгаж байгаа бол
цуцлах/татгалзах хувилбаруудыг алгасаад 19-р хэсэгт орж болно.

1. T **Нүүр → Харьяалал шилжүүлэх → Өөр салбарт шилжих**.
2. Одоогийн A, очих B, шалтгаан сонгоод **Шилжих хүсэлт илгээх**.
3. Хүлээгдэж байхад A үндсэн хэвээр; хоёр дахь pending хүсэлт үүсгэх товчгүй.
4. **Хүсэлтээ цуцлах** → баталгаажуулах цонхонд дахин цуцална. B-admin дарааллаа
   шинэчилнэ: энэ хүсэлт pending биш болсон байна. **T24**
5. T шинэ A→B хүсэлт илгээнэ. B-admin B салбараа нээгээд
   **Шилжих хүсэлтүүд → Татгалзах → Татгалзах**.
6. T нүүрээ шинэчлээд татгалзсан төлөв, A харьяалал хэвээр байгааг харна. **T25**

## 19. Шилжилтийг батлах — T26

1. T A→B шинэ хүсэлт илгээнэ.
2. M **Шилжих хүсэлтүүд** URL-ийг нээж шийдэх эрхгүйг дахин шалгана.
3. B-admin **Нүүр → B салбар руу орох → Шилжих хүсэлтүүд**.
4. T, A→B чиглэл, шалтгааныг тулгаж **Батлах**, дараагийн цонхонд дахин **Батлах**.
5. T хуучин хуудсаа refresh хийх эсвэл шинэ үйлдэл хийнэ: session хүчингүй болж
   дахин нэвтрэх шаардлага гарна. Нээлттэй хуудсан дээр шууд автоматаар үсрэх албагүй.
6. T eID-ээр дахин нэвтэрч B-г нээгээд **Миний гишүүнчлэл**-ээ шалгана.

**Хүлээгдэх:** B — **Үндсэн харьяалал · Идэвхтэй**, A — **Гарсан** түүхтэй;
үндсэн харьяалал ганц. T B-д энгийн гишүүн, admin/manager биш.
T энгийн гишүүн байсан A-ийн дотоод event/удирдлагыг цааш нээж чадахгүй.
A/B-admin нэг хүн бол B-г идэвхжүүлж байж хүсэлтийг шийднэ.

## 20. Шилжилтийн дараах түүх ба ижил сарын хураамж — T27–T29

1. T B-д нэвтэрсэн үед **Бүртгэл → Миний оролцоо, төлөлтийн түүх** нээнэ. **T27**
2. A-ийн үндсэн event, цэвэр оноо, A-ийн сарын charge, paid/үлдэгдэл, төлөлтийн
   мөрүүд шилжихийн өмнөхтэй ижил, **A салбарын нэртэй** байгааг шалгана.
3. **Холбоо барих мэдээлэл** болон өөрийн мэдэгдлийн хуучин түүх хадгалагдсан байна.
4. B-admin B-ийн санхүүд A-д ногдуулсан **яг ижил сар**-ыг ногдуулна. **T28**
5. T-ийн хувийн бүх түүхийг дахин харна: энэ сард **B-ийн хоёр дахь charge байхгүй**.
   Бусад B гишүүнд charge үүсэж болох тул нийт created=0 байхыг шаардахгүй.
6. Дараагийн сарын ногдуулалтыг тусгаарласан тестэд эсвэл байгууллагын бодит
   хуваарийн дагуу хийнэ: T-д B-ийн нэг charge үүснэ. **T29**

**Анхаарах ялгаа:** **Ирц**, **Миний хураамж** нь одоогийн B салбарынх;
A-ийн архивыг **Миний оролцоо, төлөлтийн түүх**-ээс харна. A-ийн хуучин өр B-ийн
санхүү рүү шилжихгүй. Хуучин A event-ийн мэдэгдэл дээр дарлаа гээд A-д ажиллах эрх
эргэж үүсэхгүй; хувийн оролцооны түүхийг үзэх эрх нь тусдаа.

## 21. Гишүүнчлэлийн төлөв — T30–T31

**T30: түдгэлзүүлэх ба сэргээх.** T одоо B-ийн энгийн гишүүн байна.

1. B-admin **Гишүүдийн бүртгэл** → T-г хайх → **Гишүүнчлэлийн төлөв өөрчлөх**.
2. **Түдгэлзсэн** сонгоно. Шалтгаан хоосон үед хадгалах боломжгүйг шалгана.
3. Тусгаарласан тестэд эсвэл бодит үндэслэлтэй үед шалтгаанаа бичиж хадгална.
4. T-ийн хуучин session дараагийн хүсэлтээр хүчингүй болно. Дахин нэвтрээд
   хувийн **Бүртгэл**-ээ нээнэ: B үндсэн хэвээр, төлөв **Түдгэлзсэн**.
5. T-д өөр салбарт энгийн элсэлтээр хоёр дахь үндсэн харьяалал үүсэхгүй.
6. B-admin T-г **Идэвхтэй** болгож, сэргээсэн шалтгаан бичнэ. T дахин нэвтэрнэ.
7. Түдгэлзсэн/сэргээсэн хоёр мөр, шалтгаан, огноо түүхэнд үлдсэнийг шалгана.

**Хүлээгдэх:** энгийн T түдгэлзэхэд B-ийн ажиллах боломж хаагдана; хувийн түүх
устахгүй. Шинэ хураамж идэвхгүй үед ногдохгүй, өмнөх өр арилдаггүй.
Үүнийг charge-аар шалгах бол T-д **өмнө нь ногдуулаагүй өөр сар**, тусгаарласан
сан ашиглана; хуучин сарын charge хэвээр байх нь хэвийн.

**T31: нэмэлт төлөвүүд — тусгаарласан тестэд тус бүр active-ээс эхэлж шалгана.**

| Төлөв | Үндсэн харьяалал | Шинэ хураамж | Энгийн гишүүний ажиллах эрх |
| --- | --- | --- | --- |
| Идэвхтэй | Хадгална | Ногдоно | Нээлттэй |
| Түдгэлзсэн | Хадгална | Ногдохгүй | Хаагдана |
| Хугацаа дууссан | Хадгална | Ногдохгүй | Хаагдана |
| Гарсан | Дуусгана | Ногдохгүй | Хаагдана |
| Ахмад гишүүн | Дуусгана | Ногдохгүй | Хаагдана |

Төлөв бүрт шалтгаан/түүх/session шалгана; дараа нь admin шалтгаантайгаар сэргээнэ.
Өөр салбарт primary болсон бол хуучин салбарт шууд active болгохыг зөвшөөрөхгүй.
**Ажилтны тусдаа идэвхтэй role-той хүний ажиллах эрх дээрх T-ийнхээс ялгаатайгаар үлдэж болно.**

## 22. Ажилтны эрхийн тусдаа шалгалт — T32

Тусгаарласан орчны S ажилтныг A-д active primary + manager, B-д өмнө нь
идэвхтэй ажиллах эрхтэй байдлаар бэлдэнэ. T дээр role нэмэхгүй.

1. S A→B шилжинэ; өөр B-admin батална. S дахин нэвтрэнэ.
2. B үндсэн болж, A/B-ийн өмнө нь идэвхтэй ажилтны эрх үлдсэнийг шалгана.
3. Өмнө нь бүрэн идэвхгүй болгосон manager/admin бүртгэлтэй хүнийг дахин
   элсүүлэх өөр fixture дээр хуучин өндөр эрх автоматаар сэргэхгүйг шалгана.
4. Өөрийн хүсэлтийг өөрөө шийдэх оролдлого болон эх салбарын цорын ганц admin-ийн
   шилжилт нь тусдаа хамгаалалттай; эдгээрийг бэлтгэсэн тестийн бүртгэлээр шалгана.

Энэ бэлтгэл production-д байхгүй бол `БЭЛТГЭЛ ДУТУУ` гэж тэмдэглэнэ. Бодит
цорын ганц админы эрхийг авч/шилжүүлж туршихгүй. Гишүүнчлэлийн төлөв өөрчлөх
дэлгэц нь ажилтны role өөрчлөх дэлгэц биш.

## 23. Утсанд суулгах, offline, гарах — T33–T35

**Android Chrome болон iPhone Safari дээр тус бүр үр дүн тэмдэглэнэ.**

1. Сайтад нэвтэрнэ. Android: browser цэс → **Install app / Add to Home screen**;
   iPhone Safari: **Share → Add to Home Screen**. **T33**
2. Үүссэн icon-оос нээнэ. Гишүүний нүүр эсвэл нэвтрэх дэлгэц зөв гарна.
   Суулгасан апп дотроос eID нэвтрэлтийг дахин шалгана.
3. **Нүүр → Эвент → Ирц → Хураамж → Бүртгэл**, гар/keyboard нээгдэхэд товч
   дарагдаж байгаа эсэх, босоо/хэвтээ харагдацыг шалгана.
4. Нээлттэй апп дээр Wi-Fi/mobile data-г салгана. **Интернэт холболт алга**
   мэдэгдэл гарна. Хадгалахыг оролдвол амжилттай мэт харуулах ёсгүй. **T34**
5. Сүлжээ сэргээж **Дахин оролдох** эсвэл refresh хийнэ; бодит хадгалсан төлөвтэй тулгана.
6. Хэрэглэгчийн цэсээр гараад icon-оос дахин нээнэ; өмнөх хүний profile/түүх
   серверээс уншигдахгүй. U-гаар нэвтэрвэл зөвхөн U-ийн хувийн түүх гарна. **T35**

API/нэвтэрсэн хуудас offline кэшгүй. Аппыг offline үед шинээр нээвэл browser-ийн
өөрийн offline дэлгэц гарч болно. Нээлттэй хуудасны өмнө татсан мэдээлэл дэлгэцэд
байх нь шинэ өөрчлөлт серверт хадгалагдсан гэсэн үг биш. Offline queue/автомат
төлөлт илгээх боломж одоогоор байхгүй.

## 24. Дуусгах — T36

1. Production-д туршилтаар солиод буцаах шаардлагатай өөрийн profile/мэдэгдлийн
   тохиргоог зөв төлөвт нь оруулна.
2. Төлөвийн тест хийсэн хүнийг тохирсон бодит төлөвт буцааж, дахин нэвтрүүлнэ.
   Бодит шилжилтийг зөвхөн “цэвэрлэх” гэж буцааж шилжүүлэхгүй.
3. Зөвшөөрөгдсөн туршилтын event-ийг **Засах → Төлөв → Цуцлагдсан** болгож болно.
   Цуцлах нь өмнөх ирц/оноог автоматаар арилгахгүй; хэрэгтэй залруулгыг 11-р хэсгээр хийнэ.
4. Төлөлт, өр, чөлөөлөлт, гишүүнчлэлийн түүхийг устгаж “цэвэрлэхгүй”.
   Үүссэн бодит өөрчлөлтийг checklist-д тэмдэглэж, санхүү/салбарын хариуцагчтай тулгана.
5. Checklist-ийн FAIL бүрт дараах загварыг бөглөнө.

```text
ID: T__
Огноо/цаг (Улаанбаатар):
Төхөөрөмж / OS / browser:
Хэрэглэгчийн төрөл: T / M / A-admin / B-admin / U
Идэвхтэй салбар:
Нээсэн хуудасны зам:
Дараалж хийсэн үйлдэл:
Хүлээсэн үр дүн:
Бодитоор гарсан үр дүн, алдааны текст:
Дахин давтагдсан эсэх:
Зураг/бичлэгийн нэр (хувийн мэдээлэл, QR кодыг далдалсан):
```

**Бэлэн гэж тооцох:** хийх боломжтой үндсэн алхмууд PASS; мөнгө/оноо давхардсан,
бусдын хувийн мэдээлэл гарсан, зөвшөөрөлгүй удирдлага нээгдсэн тохиолдолгүй;
FAIL болон бэлтгэл дутуу хэсгийг тусад нь жагсаасан байна. `АЛГАСАВ` эсвэл
`БЭЛТГЭЛ ДУТУУ` мөрийг PASS-д оруулахгүй.

### Хэвийн нөхцөлүүдийг алдаатай андуурахгүй байх

- Хураамж тохируулаагүй/ногдуулаагүй үед хоосон байх нь хэвийн.
- Үндсэн харьяалалгүй ажилтан ажиллах эрхтэй ч хураамжгүй байж болно.
- Шилжилт/төлөвийн өөрчлөлтийн дараах дахин нэвтрэлт нь хамгаалалтын үйлдэл.
- Өмнөх салбарын түүхийг **Миний оролцоо, төлөлтийн түүх**-ээс харна.
- Өөрчлөлтийн дараа бүх дэлгэц шууд realtime шинэчлэгдэх албагүй; refresh хийнэ.
- Автомат сарын ногдуулалт, автомат хугацаа дуусгалт/сунгалт, QPay callback,
  push/SMS/имэйл, сумдын нийлбэр тайлан энэ хувилбарт ороогүй.

Энэ заавар нь дэлгэцээс хийх хүлээн авалтын шалгалт. Давхцсан хүсэлт, өгөгдлийн
сангийн тусгаарлалт зэрэг автомат шалгалтын нотолгоог
[production тайлан](SDY_PRODUCTION_2026-09-16.md) болон
[хэрэгжилтийн тайлан](SDY_IMPLEMENTATION_2026-09-15.md)-гаас үзнэ.

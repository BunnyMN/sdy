# SDY — гурван ажлын хэрэгжилт, 2026-09-15

**Гурван ажлыг локал кодод хэрэгжүүлж, PostgreSQL/Redis болон хөтчийн тестээр
шалгасан.** Суурь: `feat/admin-approved-transfers`, `90745acc`. Энэ өөрчлөлтийг
production-д deploy хийгээгүй; өмнөх production аудитын үр дүнг шинэ runtime
шалгалт гэж үзэхгүй. Дараагийн ажлыг энэ файлаас эхэлнэ.

## 1. Үндсэн харьяалал, ажиллах эрх, хураамж

- Нэг хүнд **нэг үндсэн харьяалал** байна. `active`, `suspended`, `expired`
  нь үндсэн харьяаллыг хадгална; `left`, `alumni` нь дуусгана. `none` нь
  үндсэн харьяалал баталгаажаагүй ажиллах бүртгэл.
- Ажиллах боломжийг `memberships.active`, role/permission удирдсаар байна.
  Үндсэн харьяалал нь тусдаа `is_primary`, `member_status`, `member_since`-тай.
  Идэвхтэй `admin`/`manager`/тусгай role нь бие даасан ажилтны эрх болно.
- Салбарын **бодит admin** үндсэн харьяалал батлах, төлөв солих эрхтэй.
  Шалтгаан заавал өгнө; өөрчлөлт, үйлдсэн хүн, огноо нь append-only түүх,
  аудитад үлдэнэ. Гишүүний салбарын session хүчингүй болно.
- Шилжихэд эх харьяалал дуусаж, очих салбарт үндсэн харьяалал, `user` эрх үүснэ.
  Хоёр талын өмнө нь идэвхтэй байсан ажилтны эрх үлдэнэ. Идэвхгүй хуучин
  staff эрхийг шилжилт эсвэл дахин элсэлтээр сэргээхгүй.
- Manager элсэх хүсэлт шийдэж чадна; үндсэн харьяаллын төлөвийг тусдаа
  өөрчлөхгүй, шилжилт шийдэхгүй. Шилжих хүсэлт гаргагч өөрийн хүсэлтийг
  батлах/татгалзахгүй. Эх салбарын цорын ганц admin-ийн хуучин хамгаалалт үлдсэн.
- Хураамжийг зөвхөн `active AND is_primary AND member_status='active'` хүмүүст
  ногдуулна. **Нэг хүн, нэг сард нэг ногдуулалт** гэсэн DB unique index-тэй.
  Өмнөх салбарт ногдуулсан сарын хураамж тэндээ үлдэнэ; шинэ салбар ижил
  сард дахин ногдуулахгүй. Хуучин өр, төлөлт, залруулгыг шинэ салбарт шилжүүлэхгүй.
- Хуучин ганц идэвхтэй нийтлэгдсэн салбартай хүн үндсэн харьяалалтай болно.
  Олон салбартай хүний work access хэвээр; admin үндсэн харьяаллыг сонгох
  хүртэл шинэ хураамж ногдохгүй. Migration идэвхгүй бүртгэлийг сэргээхгүй.

Эдгээрийг тусгай хариу ирээгүй үед сонгосон хэрэгжилтийн дүрэм гэж ойлгоно.
Байгууллагын баталсан хураамжийн хэмжээ, албан тушаалын жагсаалт, гишүүнчлэл
дуусах автомат хугацаа гэсэн үг биш. Төлбөрийн тохиргоог автоматаар асаагаагүй.

| Ажилтны эрх | Шилжилтийн хоёр талын идэвхтэй work role үлдэнэ; дахин элсэлт хүчингүй хуучин staff role-ийг сэргээхгүй |
| Events | Хугацаа дууссан QR оноо өгөхгүй; давтан батлахад давхар оноогүй; батлагдсан ирцийг залруулахад шалтгаан шаардлагатай |
| Хувийн мэдээлэл | Энгийн гишүүн оролцогчдын имэйл/зохион байгуулагчийн note харахгүй; өөр хүний profile, мэдэгдэл, хуучин түүх уншиж өөрчлөхгүй |
| Хураамж | Бодит шилжилтийн дараа ижил сард давхар ногдуулахгүй; дараагийн сарын ногдуулалт зөв салбарт үүснэ |
| Санхүү | Хэсэгчилсэн төлөлт, татгалзалт, баталгаажуулалт буцаалт, чөлөөлөлт, давтан хүсэлт, ledger ба сарын үлдэгдэл таарна |

## 3. Гишүүний дэлгэцүүд ба салбарын нэгтгэл

| Зам | Боломж |
| --- | --- |
| `/member/record` | Үндсэн/өмнөх харьяалал, эхэлсэн огноо, шалтгаантай түүх; өөрийн утас, оршин суугаа газар, мэдэгдлийн тохиргоо |
| `/member/history` | Өөрийн хуучин болон одоогийн салбарын ирц, онооны хөдөлгөөн, хураамж, төлөлт |
| `/member/notifications` | Элсэлт/шилжилт/гишүүнчлэл, арга хэмжээ/ирц, хураамж/төлөлтийн апп доторх мэдэгдэл; нэгийг эсвэл бүгдийг уншсанд тооцох |
| `/member/members` | Manager/admin-ийн хайлттай бүртгэл; admin-ийн шалтгаантай төлөвийн өөрчлөлт |
| `/member/overview` | Одоогийн үндсэн гишүүд, ажиллах эрх, хүсэлтүүд; зөвшөөрөлтэй бол сонгосон сарын оролцоо, санхүү |

Мэдэгдэл бизнесийн өөрчлөлттэй нэг DB transaction-д бичигдэнэ. Ижил үйлдлийн
retry давхар мэдэгдэл үүсгэхгүй. Шинэ арга хэмжээ/цаг/байршил/төлөв өөрчлөгдөхөд
идэвхтэй үндсэн гишүүдэд мэдэгдэнэ; арга хэмжээний холбоос зөв салбарыг сонгож
нээнэ. Мэдэгдлийн тохиргоог унтраавал дараагийн мэдэгдэл үүсэхгүй, түүх үлдэнэ.

Хувийн profile болон мэдэгдлийг зөвхөн эзэн нь уншина. Салбарын manager нэмэлт
утас/хаягийг уншихгүй. Хувийн түүхийн endpoint нь session-оор таньж, SQL дээр
`app.current_user`-аар хязгаарлана; өмнөх салбарын ажиллах эрх шаарддаггүй.
Өөр салбарын бүх гишүүний түүхийг харах эрх үүсгэхгүй.

Салбарын нэгтгэл дэх **идэвхтэй гишүүд** нь одоогийн үндсэн бүртгэлийн тоо;
**оролцсон гишүүд** нь сонгосон сарын event-ийн оролцоо. Manager санхүүгийн
тусгай эрхгүй бол санхүүгийн API дуудлага ч хийхгүй.

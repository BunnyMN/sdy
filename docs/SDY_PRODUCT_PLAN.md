1. Хүн eID Mongolia апп-аар танилтаа баталгаажуулж SDY-д нэвтэрнэ.
2. Дархан-Уул аймаг болон Дархан, Орхон, Шарын гол, Хонгор сумын дөрвөн
   дэд байгууллагаас сонгож элсэх хүсэлт өгнө. Энэ нь өмнөх 21 аймгийн
   сонголтыг 2026-09-10-нд хэрэглэгчийн хүсэлтээр орлосон.
3. Тухайн байгууллагын manager эсвэл admin хүсэлтийг шийдвэрлэнэ.
4. Батлагдсан хүн тухайн байгууллагын гишүүн болно.
5. Manager/admin арга хэмжээ үүсгэж удирдана.
6. Гишүүн арга хэмжээнд оролцож, ирцээ бүртгүүлж, үнэлгээний оноо авна.
7. Систем гишүүний идэвх, оролцоо, сарын суурь хураамжийн төлөлтийн түүхийг хөтөлнө.

Энэ тодруулга нь өмнөх «арга хэмжээг зөвхөн admin үүсгэнэ» гэсэн тайлбарыг
орлоно: **manager болон admin хоёул арга хэмжээ удирдана**.

## Хэрэгжүүлэхийн өмнөх суурь

- eID танилт, танигдсан хүний дансыг олох/шинэ данс үүсгэх, session бий.
  Бодит утасны eID нэвтрэлтээс элсэлт хүртэлх production урсгалыг хараахан
  бүрэн туршаагүй. Callback одоогоор `/profile` рүү шилжүүлдэг.
- Байгууллагын лавлах, элсэх хүсэлт, батлах/татгалзах, membership үүсгэх,
  хүсэлтийн хариуг хүний дэлгэцэд хүргэх суурь бий.
- Элсэх хүсэлт шийдэх API одоо `/admin/access`-ийн `RequireAdmin` хамгаалалтад
  байгаа. Manager-т зориулсан тусдаа permission болон queue дэлгэц хэрэгтэй.
  Role болон permission өөрчлөх одоогийн админы эрхийг manager-т нээхгүй.
- Одоогийн directory нь бүх идэвхтэй organisation-ийг хамарна. Серверт
  `on_request` бодлоготой 22 organisation, 2 personal workspace байна.
  Гишүүний сонголтод зөвхөн албан ёсны 21 салбар гарахыг тусад нь батална.
- Events-ийн `events.manage` нь admin болон анхдагч manager role-д,
  `events.read` нь member-д бий. Энэ нь одоогийн шаардлагатай нийцнэ.
- Гишүүний бүртгэл `registered`; зохион байгуулагчийн тэмдэглэсэн бодит ирц
  `attended/absent`. Өөрөө QR/код ашиглан ирц баталгаажуулах боломж байхгүй.
- Оноо, гишүүний сарын хураамжийн зориулалтын ажиллаж буй модуль, schema,
  API каталогт илрээгүй. Тайлангийн хөдөлгүүр нь байгаа ч эдгээрийн тайланг
  өгөгдлийн дүрэмтэй нь хамт шинээр тодорхойлно.
- Tenant RLS, байгууллагын role/permission, аудит, платформын тусдаа
  операторын урсгал бий. Гишүүний хураамж, онооны дэлгэрэнгүйд байгууллагын
  хилийн зэрэгцээ өөрийн мэдээллийг харах эрхийн хязгаар нэмэх шаардлагатай.
- Production `debe50fe`, Events 1.0.0/schema 1. PR #7 merge/deploy болоогүй.

## Санал болгож буй бүтээгдэхүүний бүтэц

### Гишүүнчлэл

Гишүүн бус хүний нүүр нь салбар сонголт болон хүсэлтийн төлөв байна.
Хүсэлт шийдэгдэхээс өмнө байгууллагын дотоод мэдээлэл нээгдэхгүй.
Батлагдсаны дараа «Миний салбар», «Миний арга хэмжээ», «Миний оноо»,
«Миний хураамж» гэсэн хувийн нүүртэй болно.

Гишүүнчлэлийн төлөв, элссэн огноо, салбар шилжилт, гарсан/түдгэлзсэн түүх
хэрэгтэй. Платформын одоогийн membership-ийг дахин хуулж шинэ identity
үүсгэхгүй; SDY-ийн гишүүнчлэлийн бизнес мэдээллийг түүнд холбоно.

### Арга хэмжээ, ирц, оноо

Бүртгүүлэх → оролцох → ирц баталгаажих → оноо үүсэх гэсэн тусдаа алхамтай.
Зөвхөн «Оролцоно» дарснаар оноо өгөхгүй гэсэн хувилбар санал болгож байна.

Эхний хувилбар manager/admin-аар ирц батлах ажиллагаатай байж болно.
Гишүүн өөрөө check-in хийхэд хугацаатай QR/код, дахин илгээхэд давхар
ирц/оноо үүсгэхгүй хамгаалалт хэрэгтэй. eID нэвтрэлт нь хүнийг танина;
тухайн арга хэмжээнд бодитоор ирснийг дангаараа батлахгүй.

Оноог зөвхөн нэг нийлбэр тоо болгон хадгалахгүй. Ямар оролцоонд, хэдийд,
ямар дүрмээр хэдэн оноо үүссэнийг түүхтэй хөтөлнө. Ирцийг залруулахад
холбогдох оноог мөн шалтгаантай залруулна. Дүрэм өөрчлөгдөхөд өмнөх
оноо тайлбаргүй өөрчлөгдөхгүй.

### Сарын хураамж

Тухайн сарын ногдуулалт, төлбөрийн бодит бичилт хоёр тусдаа бүртгэл байна.
Ингэснээр төлсөн/төлөөгүй, дутуу төлөлт, урьдчилсан төлөлт, чөлөөлөлт,
буцаалт болон тайлан хоорондоо таарна. Мөнгөн дүнг бүхэл нэгжээр тооцно.

Эхний хувилбарт санхүүгийн эрхтэй хүн шилжүүлгийг тулгаж баталгаажуулж
болно. Төлбөрийн үйлчилгээ холбоход серверээс баталгаажсан төлөлтөөр
бичилт үүсгэж, давтан callback-ийг нэг удаа тооцно. Гишүүний илгээсэн
зураг/«төлсөн» товч нь автоматаар төлөгдсөн төлөв болгох нотолгоо биш.

### Идэвх ба тайлан

Гишүүн өөрийн оролцоо, онооны задаргаа, сарын хураамжаа харна. Manager/admin
өөрийн салбарын гишүүнчлэл, арга хэмжээ, оролцооны тайланг харна.
Хураамж баталгаажуулах эрхийг тусад нь өгнө. Төвийн нэгтгэлд тусгай
бизнес эрх шаардлагатай; техникийн операторын эрхтэй адилтгахгүй.

Салбар хооронд идэвх харьцуулах бол арга хэмжээний тоо, хамрагдах боломж,
хугацааг харгалзана. Онооны нийлбэр ганцаараа шударга харьцуулалт болж
чадахгүй байж болно; эхлээд ил тод оролцооны үзүүлэлтүүд гаргана.

## Хэрэгжүүлэх дараалал

1. **Нэвтрэлт ба элсэлт:** 21 салбарын сонголт, хүсэлтийн төлөв,
   manager/admin-ийн шийдвэрлэх permission/UI, батлагдсан гишүүний нүүр.
   Тестийг production-ийн startup migration дараалалтай нийцүүлж шалгана.
2. **Events ба ирц:** өмнөх багтаамжийн засвар, гишүүн/manager/admin урсгал,
   баталгаатай ирц, давхардлын хамгаалалт, ирцийн залруулгын аудит.
3. **Оноо:** батлагдсан дүрэм, ирцтэй холбоотой онооны түүх, гишүүний задаргаа.
4. **Хураамж:** сарын ногдуулалт, төлөлт/чөлөөлөлт/үлдэгдэл, санхүүгийн эрх.
5. **Нэгтгэл:** салбарын болон төвийн тайлан, сануулга, шаардлагатай экспорт.

Эхний ээлжийн хүлээн авах шалгуур: шинэ хүн eID-ээр нэвтрэх → салбар сонгох
→ хүсэлт өгөх → тухайн салбарын manager батлах → энгийн member болох →
manager/admin-ийн үүсгэсэн Events-ийг ашиглах. Өөр салбарын хүсэлт/өгөгдөл
харахгүй, manager role өөрчилж өөрийгөө admin болгохгүйг мөн шалгана.

## Хэрэгжүүлэхийн өмнө тогтоох бизнесийн дүрэм

- Нэг хүн нэг үндсэн салбартай байх уу; бусад салбарын event-д оролцож
  болох уу; шилжилтийн дараа өмнөх оноо/хураамжийг хэрхэн харуулах вэ?
- Ирцийг юугаар батлах, event-ийн төрөл бүрийн оноо, залруулга батлах эрх,
  сарын/жилийн үзүүлэлт хэрхэн тооцогдох вэ?
- Сарын хураамжийн хэмжээ, төлөх эцсийн өдөр, элссэн сараас тооцох дүрэм,
  чөлөөлөлт, мөнгө хүлээн авах байгууллага/данс, баталгаажуулах ажилтан хэн бэ?

Эдгээрийн утгыг хэрэглэгч хараахан өгөөгүй тул кодод дур мэдэн тогтоохгүй.
